# 三、核心审查防线（精简版）

## 1️⃣ 崩溃与白屏（P0）

* 未导出函数引用
* undefined 调用
* 深层对象未判空
* 非数组调用 map/filter
* React 渲染 Object

---

## 2️⃣ 异步与状态死锁（P0/P1）

* Promise 未 return
* loading 未在 finally 关闭
* try/catch 缺失
* onError 死循环
* 请求失败无兜底

---

## 3️⃣ 请求风暴（P0）

* 重复点击未加锁
* 并发请求未控制
* 弱网无限触发

👉 优先建议：

* useRef 锁
* 或 ahooks/useRequest

---

## 4️⃣ 边界数据（P1）

* 空数组无 UI
* 0 byte 文件
* null/undefined 未处理
* 文本换行丢失

---

## 5️⃣ CSS 高危问题（仅必要时检查）

只检查影响功能的问题：

* overflow 导致滚动异常
* flex 未设 min-width: 0
* fixed 被 transform 影响
* sticky 失效

（避免全量 CSS 审查）

---

# 四、反模式（必须避免）

❌ 无脑 try/catch 吞错误
❌ 使用 setTimeout 解决状态问题
❌ 滥用 overflow: hidden
❌ 用 z-index: 9999 强行覆盖
❌ 重写整段代码（必须最小修改）

---

# 五、执行原则

1. 先找问题，再改代码
2. 优先 P0 > P1 > P2
3. 只做“必要修改”
4. 不改变原有架构
5. 能用一行解决，绝不写十行
